# Upload Workspace Datasets to Platform

This plan outlines the steps to add an endpoint that pulls workflow results (datasets) from the `airflow-workspace` MinIO bucket and automatically uploads them to the digitaltwins platform database.

## Proposed Changes

### 1. API Router 
**[MODIFY] [upload.py](file:///home/clin864/Projects/digitaltwins-platform/services/api/digitaltwins-api/app/routers/upload.py)**
We will add a new endpoint: `POST /assays/{assay_id}/workspace/dataset/upload`

**Endpoint Logic:**
1. **Timestamp Resolution**: Accept an optional `timestamp`. If not provided, use `MinioDownloader.get_latest_timestamp_folder` to find the most recent workflow run for `assay_{assay_id}` in `airflow-workspace`.
2. **Fetch Assay Configs**: Call `querier.get_assay(assay_id, get_configs=True)` to retrieve the assay's outputs configuration. This allows us to map each `dataset_name` (folder name) to its proper `category` as stored in Postgres.
3. **Download from Workspace**: Use `MinioDownloader.download_folder` to download the entire `assay_{assay_id}/{timestamp}/` folder to a temporary local directory.
4. **Upload to Platform**: Iterate through each subfolder inside the downloaded directory (e.g., `converted_dataset`).
    - Match the subfolder name to a `dataset_name` in the assay configurations to determine its `category` (defaulting to `"workflows"` if no match is found).
    - Call `uploader.upload_dataset(dataset_path=..., category=category)`.
    - Collect the generated `dataset_uuid` for each uploaded dataset.
5. **Cleanup**: Remove the temporary directory.
6. **Return**: Return a list of all successful `dataset_uuid`s and their corresponding dataset folder names.
