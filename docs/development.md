# Ongoing development in the shared environment

How to get a change from the repo into the running platform on a shared box
(`staging`, a compute node, etc.), and what *extra* each kind of change needs.

> **Living document.** The list of "kinds of change" below is not exhaustive —
> add a row when you hit a case that isn't covered. When in doubt, the safe
> fallback is always `util/reset.sh` + a clean rebuild (see `util/README.md`).

---

## The model (read this once)

There are **two trees**:

- **`/mnt/install_src/clean_src/digitaltwins-platform`** — a real git checkout
  (submodules included). This is the *source*. You `git pull` here.
- **`~/digitaltwins-platform`** — the *runtime*. This is what actually runs.

`util/sync-runtime.sh` mirrors source → runtime with `rsync --delete`, but
**preserves environment-specific / runtime-generated state** so a sync never
wipes your box's identity. It does **not** touch:

- `.env` (generated by `gen-env.sh`)
- `services/airflow/dags/` (managed by `sync-dags.sh`)
- `services/airflow/logs/` (runtime logs)
- `services/keycloak/import/` (rendered realm)
- `services/nginx/certs/` (installed TLS)
- `services/seek/.../docker-compose.env` (rendered SEEK env)
- and it **protects** `airflow-init`'s runtime-generated files in
  `services/airflow/config/` from `--delete`, while still syncing the *tracked*
  config there (`airflow.cfg`, `webserver_config.py`).

If a generated file is *missing*, sync re-renders it. Existing ones are left alone.

## TL;DR — the common loop (code change only)

```
cd /mnt/install_src/clean_src/digitaltwins-platform && git pull --ff-only
cd ~/digitaltwins-platform && ./util/sync-runtime.sh
docker compose up -d --build          # or scoped: up -d <service>
```

Notes:
- **Prefer scoped recreate** (`docker compose up -d <service>`) over a blanket
  `up -d`. A blanket up bounces **SEEK**, which takes minutes to boot and throws
  a transient 502 on `/seek/*` — looks like a break, isn't.
- **The API is a build service** — recreating it needs `--build`.
- `docker compose down && up -d` (your instinct) works but restarts *everything*,
  including SEEK. Fine for an intentional full restart; heavy for a one-service change.
- Dry-run the sync first if unsure: `./util/sync-runtime.sh -n`.

## Change-type playbook

| You changed… | Do this |
|---|---|
| **App/service source** (a submodule, `services/*/…`) | `git pull` clean_src → `sync-runtime` → recreate the affected service (`up -d <svc>`; API `--build`). |
| **Airflow DAGs** | NOT via sync-runtime (excluded). Use `util/sync-dags.sh <SRC_HOST> <DST_HOST>`. The dag-processor rescans in ~1–2 min; no restart. **New DAGs land paused** (`dags_are_paused_at_creation=True`). |
| **Airflow config** (`webserver_config.py`, `airflow.cfg`) | Edit in repo → `sync-runtime` (now propagates) → recreate `airflow-apiserver` (and `airflow-scheduler` if `airflow.cfg`). |
| **New env variable** | Add to `.env.template` (with a sane default in the `env` file) → `gen-env.sh` → `sync-runtime` → recreate consumers. |
| **New secret** | Add to `secrets.env.template` **and** the real `secrets.env`. If it's rendered into the realm or `.env`, also add it to the `VARS` list **and** the unresolved-check loop in `gen-realm.sh` / `gen-env.sh`. Those scripts **hard-fail** on a missing/blank secret — that's your safety net. |
| **Keycloak realm** (client, role, user, mapper) | Edit `services/keycloak/digitaltwins-realm.json.template` (see `services/keycloak/REALM.md`) → `gen-realm.sh -e <env> -s <secrets>`. **The import runs first-boot only**, so pick one: (a) apply the same change live via `kcadm`/admin console, or (b) drop the realm and re-import (wipe the Keycloak DB volume → fresh import). |
| **New compose service / new image dependency** | `sync-runtime` → `up -d --build <svc>`. On a connected host, re-freeze the image archive: `util/freeze_images.sh`. |
| **TLS cert / domain** | `util/issue-cert.sh` (connected) or follow `util/domain-change.md`. Certs live in `services/nginx/certs/` and are **not** clobbered by sync — replace them explicitly, then `nginx -s reload`. |
| **Data** (datasets, buckets, DBs) | Via the portal, or `util/stage-dump.sh` → `util/portal-restore.sh`. Note the DB and MinIO can drift out of sync (the portal can know about a dataset whose objects aren't present). |
| **Inconsistent / unknown state** | `sudo util/reset.sh [--level platform\|apt\|bare]` then rebuild (`util/README.md`). This is the worst-case reset button. |

## Invariants & gotchas (the "why" behind the steps)

- **Two auth paths in Airflow, don't conflate them.** The **UI** logs in via
  Keycloak OAuth — roles come from the realm `airflow_*` roles mapped by
  `webserver_config.py` (`AUTH_ROLES_MAPPING` + `AUTH_ROLES_SYNC_AT_LOGIN`),
  re-synced **on each login**. The **API** (assay trigger) authenticates as the
  **local FAB admin** via `/auth/token` using `AIRFLOW_PASSWORD`
  (`_AIRFLOW_WWW_USER_CREATE=true` recreates it on build). A Keycloak user is a
  UI user; it is *not* the API's credential.
- **Realm import is first-boot only.** Editing the template does nothing to a
  running realm. Re-import means an empty Keycloak DB volume.
- **`gen-realm.sh` / `gen-env.sh` self-validate.** They fail loudly on any
  unresolved `${VAR}`. Lean on that instead of maintaining a separate checklist —
  it can't drift, because it's derived from the templates the app actually uses.
- **Celery queues:** the local worker serves **`default`**; the **`remote`**
  queue is **parked** (no consumer) until a compute node + task tagging go live
  together. Tasks on a queue nobody serves sit in `queued` forever.
  `WORKER_QUEUES` is a **compute-node** variable — it does not belong in the
  platform `.env`.
- **Realtime task logs** for a *running* task are on the **worker's local disk**;
  the `airflow-logs` MinIO bucket only gets them on completion.
- **Don't casually blanket `up -d`** — SEEK bounce (above).
- **`reset.sh` runs from the bundle copy**, not the runtime it deletes, and
  `--dry-run` first.

## Quick reference — where things live

| Thing | Path |
|---|---|
| Source checkout (pull here) | `/mnt/install_src/clean_src/digitaltwins-platform` |
| Runtime (what runs) | `~/digitaltwins-platform` |
| Env / secrets (per-box) | `<DATA_DIR>/env`, `<DATA_DIR>/secrets.env` (rendered → runtime `.env`) |
| Realm template / reference | `services/keycloak/digitaltwins-realm.json.template`, `services/keycloak/REALM.md` |
| Airflow config | `services/airflow/config/{airflow.cfg,webserver_config.py}` |
| Install / rebuild runbook | `util/README.md` |
